## 1. 설계를 안 정한 채로 코드를 쳤다 (208)

````python
node = self.child                          # self.child 는 딕셔너리
if node.child not in data:                 # node 에 .child 를 요구 → 객체 가정
    self.child.setdefault(..., {})         # 자식으로 {} 를 넣음 → 딕셔너리 가정
````

한 줄은 "자식은 객체"라고 믿고, 다음 줄은 "자식은 딕셔너리"라고 믿는다.
둘 다 참일 수 없다. `{}` 에는 `.child` 가 없으니까.

**문법 실수가 아니라, 코드가 자기가 뭘 다루는지에 대해 두 가지로 대답하고 있었다.**
하나씩 때워도 계속 튀어나온다. 뿌리가 하나라서.

→ 자료구조 문제는 **자식 자리에 들어갈 물건이 무엇인지** 한 줄로 정하고 시작.
그게 안 정해졌으면 아직 코드 칠 때가 아니다.

## 2. 버그 두 개가 서로를 가려줬다 (208)

`insert` 는 `end` 를 **마지막 글자의 부모** 노드에 찍고 있었다.
`search` 도 **같은 자리**에서 `end` 를 읽고 있었다.

쓰는 쪽과 읽는 쪽이 똑같이 한 칸씩 밀려서 **LeetCode 예시가 통과한다.**

````
insert("ab") → 'a' 노드에 end 가 찍힘   ('b' 가 아니라)
insert("acd")
search("ac") → True                    ← 넣은 적 없는 단어
````

`'a'` 는 자식을 여러 개 가진다. "내 자식 중 하나에서 끝났다"는 정보로는 **어느 자식인지 모른다.**

→ **예시가 통과했다 ≠ 맞다.** 특히 대칭인 두 함수를 같이 고쳤을 때.
한쪽만 고치면 통과하던 테스트가 깨지는데, 그게 정상이다.

## 3. 리턴은 하나인데 값이 두 개 필요했다 (124)

노드 20 에서:

````
부모에게 올려보낼 값 :  20 + max(15, 7)      = 35   ← 한쪽만 (꺾이면 못 이어붙임)
정답 후보로 챙길 값  :  20 + 15 + 7          = 42   ← 양쪽 다
````

리턴 자리를 35 가 차지하면 **42 는 그 호출이 끝나는 순간 사라진다.**
루트가 받은 건 9 와 35 뿐이라 거기서 42 를 만들 방법이 없다.

증상을 알아채는 법 — **정답 숫자가 계산 과정 어디에도 등장하지 않는다.**
손으로 추적했을 때 42 가 안 나오면 그 시점에 이미 설계가 틀린 거다.

→ 호출이 끝나도 살아남는 자리가 필요하다. (밖의 변수 / 튜플 반환)

## 4. 정보 흐름 방향을 반대로 잡았다 (124)

`total`(루트에서 여기까지 온 합)을 인수로 **내려보내려** 했다.
그런데 정답 경로 `15 -> 20 -> 7` 은 루트를 안 지난다. 위에서 온 값이 뭐든 답은 42다.

→ 인수를 하나 추가하기 전에 **"이 값을 받아서 뭘 할 건가"** 한 문장.
못 대면 그 인수는 필요 없다.

## 5. 채팅에 쓴 규칙이 코드에 없었다 (124) ← 오늘 제일 비쌌다

````
설계 단계 : "큰거 + x가 0이상이다 ㅇㅋ 이값을 리턴, -다 버림"
              ↓  (약 1시간, 클래스 문법 삽질이 끼어듦)
코드      : 버리는 부분이 없음  →  [1,5,-3] 에서 6 대신 5
````

그 문장은 분명히 머릿속에 있었다. **정돈이 안 된 게 아니라 휘발됐다.**
레지스터에 있던 값을 인터럽트 전에 스택에 안 밀어넣은 것.

→ 머릿속 저장은 컨텍스트 스위칭에 안 버틴다. 종이 여백에 한 줄.

## 7. 규칙을 만든 예제로 그 규칙을 검증했다 (72)

`horse × rose` 격자에 v/x 찍어서 "대각선 연속 글자수" 규칙을 뽑았다.
검증한 건 `horse/ros` 와 `cog/ros`. **둘 다 규칙을 뽑을 때 쓴 데이터다.**

세 번째 예제가 없었다. `intention/execution` 은 **문제가 제공한 예시인데도** 안 넣어봤다.

````
'ab' -> 'ba'
연속 공통 글자 = 1        규칙: max(2,2) - 1 = 1        정답: 2
````

살린 글자 1개당 연산 1번이 아니다. 안 살린 글자가 몇 번씩 드는지가 위치마다 다르다.

→ 6번과 뿌리가 같다. **자기 아이디어를 깨려고 만든 예제가 없고, 확인하는 예제만 있다.**
설계 단계에서 나오면 "잘못된 규칙", 코드 단계에서 나오면 "안 잡힌 버그".

## 8. 처음 배운 것 — 클래스

````python
self.count = 0     # 인스턴스 변수. 대입하는 순간 생김. C 의 self->count

count = 0          # __init__ 안에서 self 없이 → 그냥 지역변수. 에러 안 남
                   # 나중에 c.count 쓸 때 AttributeError. 원인과 증상이 멀다

class Cart:
    items = {}     # 클래스 몸통의 가변 객체 → 모든 인스턴스가 하나를 공유 (C 의 static)
                   # 노드 수백 개짜리 자료구조에서 이걸 하면 증상이 기괴해진다
````

`self.` 는 필드에도 메서드에도 붙는다. `self.take(...)`. 안 붙이면 `NameError`.

**클래스를 쓰는 조건은 두 개고 둘 다 맞을 때만이다.**
① 같은 모양의 데이터 묶음이 여러 개 ② 그 묶음마다 딸린 동작.
트라이 노드가 수백 개에 전부 `children` + `end` 라서 쓴 거지, 트라이라서 쓴 게 아니다.

## 9. 배열 인덱싱은 트리에 안 쓴다 (124)

`2x+1 / 2x+2` 를 쓰려고 했는데, 그건 트리가 빽빽할 때만 성립한다.
한쪽으로 3만 개 이어지면 배열 칸이 2^30000 개 필요하다. 포인터는 3만 개면 3만 개.

애초에 입력이 리스트가 아니라 `TreeNode` 객체였다. `2x+1` 이 이미 `.left` 로 만들어져 있었다.
`[-10,9,20,null,null,15,7]` 은 **문제 설명용 표기**지 실제 자료구조가 아니다.
