# 127 Word Ladder 에서 밟은 것들

## 1. 같아 보인다 ≠ 같다

````python
find_words = wildcards.get("".join(y))   # 리스트   ['cog']
end_check  = "['" + endword + "']"       # 문자열   "['cog']"

if find_words == end_check:   # 영원히 False
````

`print` 로 둘 다 찍으면 화면에 똑같이 `['cog']` 라고 나온다.
`print` 는 읽기 좋은 모양만 보여주고 타입을 숨기니까, **화면이 같은 건 증거가 아니다.**

앞으로 "같아 보이는데 왜 안 걸리지" 상황이면:

````python
print(repr(x), type(x))
````

`repr()` 은 파이썬이 읽는 표기를 그대로 보여준다. 문자열이면 따옴표가 같이 나온다.

지난주 위상정렬 때의 **"에러가 사라졌다 ≠ 고쳤다"** 랑 같은 집안이다.

## 2. 타입 뒤에 숨어 있던 진짜 실수

타입을 맞춰도 여전히 틀렸다. `*og` 버킷은 `['dog', 'log', 'cog']` 인데
버킷 **전체**를 `['cog']` 랑 비교하고 있었다.

물어야 했던 건 "이 버킷이 곧 endWord인가"가 아니라 **"endWord가 이 안에 있는가"**.
`in` 은 두 줄 아래에서 이미 쓰고 있었다.

→ 타입은 눈앞의 장애물, **어떤 질문을 하고 있는가**가 그 뒤의 진짜 문제.

## 3. 큐를 순회하면서 동시에 빼기

````python
for word in queue:
    node = queue.popleft()   # word 와 node 가 서로 다른 단어
````

C 의 배열 감각이 그대로 왔다. `deque` 를 `for` 로 돌리면서 안에서 빼면
순회 중인 컨테이너를 변형하는 거라 건너뛰기가 생긴다. 게다가 변수가 두 개로 갈렸다.

지난번 위상정렬 노트에 적은 "C 처럼 사용하는 배열" 이 또 나왔다.

n = len(endword)

## 5. 안 돌려보고 가져갔다

BFS 초안에 독립적인 고장이 **다섯 개** 있었다.
메서드/파라미터 이름 소문자, `deque` import 누락, 위의 3번, 4번, `[wildcards.get(...)]` 대괄호.

다섯 개가 겹쳐 있으면 **뭐가 뭘 깨뜨렸는지 안 보인다.**
한 개 고치고 → 돌리고 → 한 개 고치고 → 돌리고.

## 6. 비용 계산을 건너뛰었다

"전수 비교하면 몇 번?" 이라는 질문에 감으로 답하고 넘어갔다. 실제로는:

````
C(5000, 2) x 10 = 1.25e8      ← 파이썬으로 10초 이상
와일드카드      = 5e5          ← O(N x L^2)
````

숫자를 냈으면 전수 비교 가지는 그 자리에서 잘렸다.

## 7. (글자, 자리) 인덱스를 와일드카드랑 같다고 생각했다

````
(글자, 자리)   →  10글자 중 1글자 고정, 9글자 자유   →  버킷 최대 N개
와일드카드     →  10글자 중 9글자 고정, 1글자 자유   →  버킷 최대 26개
````

그리고 더 결정적인 것 — **단어 길이가 1이면** (글자, 자리) 인덱스는
느린 게 아니라 **이웃을 아예 못 찾는다.** `a` 와 `c` 는 공유하는 키가 없으니까.
와일드카드는 `*` 하나로 다 묶여서 멀쩡히 돈다. 성능 차이가 아니라 정답 차이였다.
